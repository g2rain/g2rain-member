# g2rain-member v1.0.0

## 首次 GHCR 镜像发布

`g2rain-member` 是 G2rain（谷雨）开源智能体平台中的会员主数据与外部身份绑定领域服务。它交付租户内会员主数据、稳定会员编号、会员状态、外部身份绑定，以及企业微信可信渠道的会员解析与幂等创建；它不负责平台登录、OAuth/OIDC、Token 签发、网关入口鉴权、企业微信回调解密或下游咨询、工单、订单和权益业务。平台整体能力与状态以 [g2rain 中央仓库](https://github.com/g2rain/g2rain) 为准：现有 SaaS 基座和知识库可用，智能体平台与智能客服已开发完成并开源，交易、订阅、计量计费等商业化能力仍处于规划设计中。

## 构建与运行要求

- Java 25、Maven 3.9+；完整构建与测试命令为 `mvn clean verify`。
- 运行时依赖 MySQL 8.0.13+、Redis 和 Nacos；默认 profile 为 `dev`，HTTP 端口为 `8080`。
- 项目版本事实源为根 `pom.xml` 的 `<revision>1.0.0</revision>`；根 parent 是 Spring Boot `4.1.2`，Spring Cloud 为 `2025.1.4`，Jib 为 `3.5.2`，Java 编译 release 为 `25`。

## 镜像与发布顺序

镜像地址为 `ghcr.io/g2rain/g2rain-member`。成功发布会同时推送 `1.0.0` 和 `sha-<完整提交 SHA>`；不推送或更新 `latest`。

1. 将发布改动、同版本发布说明和验证结果先合入实际发布分支 `main`。
2. 在已验证的 `main` 提交创建并推送 `v1.0.0` tag。
3. 工作流验证稳定 tag 格式、`origin/main` 可达性、本文件和 Maven 项目版本，运行 `mvn -U clean install` 后才构建并推送两个标签。
4. 镜像 job 成功后，同一 tag 提交调用 Maven 工作流，发布根父 POM 与 API 模块到 `https://maven.pkg.github.com/g2rain/g2rain-member`；坐标为 `com.g2rain:g2rain-member:1.0.0`（POM）与 `com.g2rain:g2rain-member-api:1.0.0`（JAR、POM、sources JAR）。

GHCR job 构建和推送镜像，后续 Maven job 发布 API；不创建 GitHub Release、不部署服务。Maven 失败不会回滚已推送的镜像，重复发布同一稳定版本可能冲突。首次成功推送后，维护者须在 GitHub Packages 的 **Package settings → Change visibility → Public** 将包设为公开；若组织管理员禁止修改，请联系管理员。已有同名 GHCR 包推送被拒绝时，还须在 **Package settings → Actions access** 授予 `g2rain-member` 写权限，并检查组织 Packages 策略；`packages: write` 不能绕过这些设置。

## 镜像内容、元数据与安全

Jib 从 `eclipse-temurin:25.0.4.1_1-jre` 生成最终镜像，打入 Startup 的 Spring Boot 可执行 Jar（应用 classes、resources 与依赖），主类为 `com.g2rain.member.Application`，容器声明端口为 `8080`。镜像采用 Apache-2.0 许可证，并带有 OCI `source`、`licenses`、`title`、`version` 和 `description` 元数据。

Jib 不会像 Dockerfile 一样复制整个工作区；本仓库没有 Dockerfile 或 `.dockerignore`。但已跟踪的 `g2rain-member-startup/src/main/resources/application-dev.yml` 会作为 Startup resource 打入可执行 Jar，因而进入镜像；它含有开发数据库用户名和密码。生产环境必须通过受控的环境变量、Secret 或 Nacos 注入并覆盖数据源及其他凭据，不能依赖镜像中的开发配置；维护者应评估和轮换任何已暴露的默认凭据。本发布准备未删除文件或改写 Git 历史。
