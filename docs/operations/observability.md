# 可观测性规范

## 日志

- 使用统一日志框架，不使用 `System.out` 或 `printStackTrace`。
- 记录可定位问题的业务标识、租户标识、状态、耗时和错误码。
- 不记录 Token、密码、密钥、验证码、完整手机号、完整外部资料或客服消息。
- 对 `organId`、`memberId`、`memberNo` 等标识的记录应符合平台隐私和审计策略。
- 可预期业务失败与系统异常区分日志级别，避免正常拒绝产生大量错误堆栈。

## 指标

建议为关键流程提供：

- 企业微信会员解析请求量、成功率和耗时。
- 首次创建、命中已有身份、唯一键冲突回查和业务拒绝次数。
- 数据库连接、慢查询和事务失败。
- 跨租户不一致、损坏绑定等需要关注的安全或数据质量事件。

指标标签不得使用 `memberId`、`externalUserId` 等高基数字段。

## 健康检查与告警

- Actuator 提供 `health`、`info` 和 `metrics`，生产环境限制访问范围。
- 告警应覆盖服务不可用、数据库异常、持续错误率、延迟突增和数据一致性异常。
- 健康检查不能执行会创建会员、改变状态或调用不稳定外部业务的操作。

## 链路定位

- 沿用 Gateway 或平台生成的请求/Trace 标识，并在内部服务调用中继续传递。
- 日志、指标和错误响应使用统一错误码关联，不暴露内部异常细节。
- 跨服务问题应能区分 IAM 验证、企业微信接入、Gateway 转发和 Member 领域处理阶段。

新增关键业务流程时，应在需求和完成定义中说明需要的日志、指标、告警及敏感信息限制。
