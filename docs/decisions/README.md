# 架构决策记录

本目录记录会长期影响模块边界、会员模型、身份唯一性、租户隔离、接口兼容性、安全或运行方式的决策。

## 何时新增 ADR

- 新增、拆分或合并 Maven 模块。
- 改变 `startup → biz → api` 依赖方向。
- 新增会员身份类型或改变身份唯一键、删除与恢复策略。
- 改变可信内部接口、租户上下文或跨服务职责边界。
- 引入新的数据库、消息系统、安全机制或部署模式。
- 一个方案存在多个合理选择，需要保留取舍理由。

普通缺陷修复、局部重构和临时实验通常不需要 ADR。

## 命名与模板

```text
0001-short-decision-title.md
```

```markdown
# 标题

## 状态

建议 / 已接受 / 已废弃 / 已替代

## 背景

需要解决的问题、约束和上下文。

## 决策

采用的方案及明确边界。

## 后果

收益、代价、风险和后续工作。
```

已有专题设计保留在 `docs/design`；其中稳定且具有长期约束的决定可以再提炼为 ADR。
