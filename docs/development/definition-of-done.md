# 完成定义（Definition of Done）

需求只有在下列适用项完成后才能标记为完成。Agent 应逐项核对，不以“代码已生成”代替验收。

## 需求与范围

- [ ] 实现满足需求目标、验收条件和明确的非目标。
- [ ] 未擅自扩大到其他项目、外部系统或未授权的数据变更。
- [ ] 未确定事项已明确报告，没有用猜测替代业务决策。

## 架构与代码

- [ ] 保持 `startup → biz → api` 模块依赖方向。
- [ ] Controller、Service、DAO、Domain 和 Converter 职责符合规范。
- [ ] API、DTO、VO、PO 没有越层或不必要耦合。
- [ ] 新依赖具有必要性、兼容性和版本依据。
- [ ] Git Diff 中没有生成器误覆盖、调试代码、无关格式化或敏感信息。

## 会员领域与安全

- [ ] 请求、身份和会员的 `organId` 一致性已验证。
- [ ] `WithoutIsolation` 使用具有受信边界和显式租户校验。
- [ ] 事务、并发、幂等、唯一键、逻辑删除和历史身份占位已处理。
- [ ] 输入、错误响应、日志和持久化资料符合最小化与脱敏要求。
- [ ] 公开接口通过 Gateway；内部接口具备真实访问控制，不只依赖路径或文档隐藏。

## 测试与验证

- [ ] 正常、边界、失败和回归场景具有必要测试。
- [ ] 数据库和 Mapper 行为在需要时由集成测试验证。
- [ ] `mvn clean verify` 通过，或未执行原因及风险已明确报告。
- [ ] 配置、启动类、端口、POM 模块和文档声明一致。

## 文档与交付

- [ ] API、数据库、配置、命令、架构或使用方式变化已同步到文档。
- [ ] 长期架构取舍已增加或更新 ADR。
- [ ] Markdown 相对链接有效，`docs/project.yaml` 的必需文档清单完整。
- [ ] PR 描述包含影响范围、验证结果、兼容性、部署和回滚要求。

不适用项可以跳过，但应能说明原因。需要测试环境、外部服务或人工验收的事项不能被 Agent 宣称为已验证。
