# 测试策略

## 原则

- 测试覆盖业务行为和边界，不只追求行覆盖率。
- 缺陷修复应先形成可复现问题的回归测试。
- 测试名称表达“场景、条件、期望”，失败时能直接定位规则。
- 单元测试不依赖共享数据库、网络、Nacos 或执行顺序。
- 涉及 SQL、事务、唯一键或框架配置的行为应由集成测试验证，不能只用 Mock 推断。

## 分层要求

| 层级 | 重点验证 |
| --- | --- |
| Domain | 纯业务规则、边界值、格式、确定性和非法输入 |
| Service | 状态变化、事务、幂等、并发冲突、租户一致性和异常映射 |
| DAO/Mapper | SQL 条件、分页、逻辑删除、大小写敏感、唯一键和数据隔离 |
| API/Controller | 参数校验、路由、响应结构、错误码和访问入口 |
| Startup | Bean 组装、配置绑定、Mapper 扫描和关键 profile 启动 |

## Member 最低场景矩阵

### 会员编号

- 相同正数 ID 生成相同编号。
- 编号以 `M` 开头且使用大写 Base36。
- 非正数、极值和非法输入按设计处理。

### 企业微信会员解析

- 已有有效身份返回既有会员。
- 首次识别在同一事务创建会员和身份。
- 并发唯一键冲突回滚新建记录并回查已有身份。
- 已删除身份拒绝自动创建或转移。
- 会员不存在、已删除、冻结或跨租户时返回明确结果。
- 请求、身份和会员的 `organId` 必须一致。
- `externalUserId` 去除首尾空白但不改变大小写。
- 外部资料只保存白名单字段，响应和日志不泄露敏感内容。

### CRUD 与数据隔离

- 新增、更新、删除和不存在记录。
- 列表及分页条件正确。
- 默认查询受租户隔离约束。
- `WithoutIsolation` 路径具有显式租户校验和受信调用边界。

## 测试命令

完整验证：

```bash
mvn clean verify
```

业务模块及依赖：

```bash
mvn -pl g2rain-member-biz -am test
```

指定测试类：

```bash
mvn -pl g2rain-member-biz -am -Dtest=MemberNoGeneratorTest test
```

## AI Coding 验证报告

Agent 完成任务时应报告：

- 新增或修改了哪些测试场景。
- 实际执行的命令及结果。
- 未执行的测试及原因。
- 仍需要真实数据库、测试环境或人工协作验证的风险。
